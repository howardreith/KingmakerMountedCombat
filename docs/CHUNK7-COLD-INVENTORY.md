# Guarded native bootstrap cold inventory

Status: IN PROGRESS. This is source support for the selected Chunk 7B–7D mission.
It does not qualify a mounted fixture or ordinary acquisition.

The closed scenario is `chunk7-bootstrap-cold-inventory`, case
`authored-readonly-inventory`. It accepts only an actual successful
`chunk7-native-main-bootstrap` output from the same source commit, DLL hash and
MVID, with base-game-only native inventory and exact transaction restoration.
The selection pins the source run, artifact hash and native Auto_1 archive hash.
Admission is repeated before staging, under the owned runtime lock, and after the
cold process. Working remains an immutable authorization anchor; the engine-minted
campaign is a separate qualified input. Existing Working-only scenario guards
remain unchanged.

The source validator reads only the qualified archive's unique header.json and
kmc-mounted-state members, bounded to 1 MiB and 128 KiB respectively. Header
campaign/name/area/category and the empty schema-3 pair/participation/slot/combat
graph must agree with the successful native writer. Duplicate JSON keys and
changed bytes refuse admission. Successful metadata decoding grants no native
restoration authority.

The isolated native scope admits exactly one load of that immutable Auto_1 and
zero writes. Observers are owned before patch installation and before the guarded
loader runs. Proof requires native PostLoad, exact campaign/area/main actor/party
and blueprint identities, no extra preparation or supplementary debt restore,
and zero mounted owners, slots, casts, snapshots and writes. Pending load, save
worker, command or unpatch work retains cleanup ownership. An expired deadline
writes a separate failed pending receipt; it never makes unsettled work complete.

The inventory records actual native money, hire cost, default inherited hire XP,
actor level/XP and level readiness, field capacity, and available Small body/rig
metadata. The fixture-readiness extension records XP rate, exact main class and
archetype ranks, effective save settings, and the sole isolated native save
descriptor. Autosave slots retain their native Single value; this observation
does not infer an integer capacity. Active slot projection or a slider fallback
callback refuses observation. Static main/locked party facts do not qualify
future selector membership or removal: the live selector has not been opened. It issues no purchase, build choice, XP or money grant, command, mode
change, profile admission or resource operation. Catalogue observation is not
Small pose proof; a measured reviewed private Small declaration may be developed
before owner visual and HUMAN PLAY acceptance.

A bootstrap archive from an older DLL cannot qualify this bridge on changed
candidate bytes. The next native dependency is a successful base-only bootstrap
on the integrated candidate, followed by its separate guarded cold-load run and
exact restoration. Its observed readiness then determines an explicit fixture
and output-slot plan. The older ordinary acquisition family cannot silently load
this new campaign, and its immutable Auto_1 cannot silently become a writable
level-up slot. Fresh main-character creation, paid companion creation, ordinary
Horse selection, mounted combat, progression, Small pose and six-pair stress
remain distinct required evidence.
