# Mounted Shield — behavioral acceptance

These rows are requirements, not executed results. All begin **NOT_RUN**. The preparation-time PNG checks in ART.md do not constitute native feature acceptance.

Use the same production calculation and actual integration paths. A small pure policy test can establish arithmetic; it cannot establish equipment reads, real AC stacking, rule timing, serialization or UI. Prefer genuine engine objects where practical and realistic thin boundary fakes where unavoidable. Keep forced fixture rolls labeled; do not present them as naturally observed random results.

**Efficient execution:** group rows into a small set of existing guarded scenarios. A row is not a separate game launch. Use one affected focused entry point and relevant neighbors, not the historical Full campaign. Verify a current frozen binary once unless a concrete changed risk requires another pass.

**Evidence statuses:** PASS, FAIL, NOT_RUN, BLOCKED and PARTIAL are allowed in this human ledger. The factory developer report has only pass/fail/not_run validation enums: explain BLOCKED/PARTIAL in scope_and_limits. Do not count a row as PASS when its required native part is missing. Preserve required rows if platform/fixture access prevents them; source completion alone does not waive final acceptance.

## Evidence to retain

For each row, record candidate source and DLL/resource identity, actual command/scenario, expected versus observed behavior, status, relevant screenshot/log/receipt and precise limits. A single evidence item can support several rows when the relationship is explicit. Use existing native records for attack/check totals, D20/DC, attempt/Swift state and ownership rather than an independent invented calculator.

Before live use, retain the independent scoped production/safety review required by the repository. After runtime checks, retain the complete factory review and final status. These evidence types serve different purposes.

If a baseline X05 save/door issue prevents a lifecycle observation, record the reproduction and separation from the new feature. Do not declare that baseline fixed, hide an attributable regression, or expand the feat into a general save-system repair.
