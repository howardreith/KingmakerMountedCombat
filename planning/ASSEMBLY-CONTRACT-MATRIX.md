## Wrath state, entry, exit, and failure summary

- Relationship state is reciprocal and serialized. Mounting validates the master/pet relationship, assigns both halves, disables rider avoidance, toggles the system ability, ensures rider IK, then raises the mount event.
- Dismount clears both halves, restores avoidance, calculates a navmesh-aware side position, disables the ability, and removes the rider part.
- No transaction or `try/finally` spans Wrath's multi-step transition. Invalid direct `Ensure<UnitPartRider>().Mount(...)` can leave an empty part; exceptions can leave partial state until controller or post-load repair.
- Controller invalidation covers consciousness, prone, swallowed, pit, hostility, master/pet/polymorph, and size. It does not use combat start as a cleanup boundary.
- View detach alone does not dismount. Serialization intentionally preserves valid relationships.

## Pre-code gate

The contract portion of the gate is PASS for a bounded, diagnostic movement slice:

- one exact rider/pet pair can be validated from existing reciprocal descriptor state;
- rider command creation can be suppressed/rerouted at a scoped origin;
- the mount can remain the sole ordinary pathing mover;
- rider avoidance can be disabled/restored through the existing reference-counted property;
- the missing Wrath movement-controller sync can be reproduced in an isolated active-pair service;
- selection/formation can be projected through an effective-unit mapping rather than changing global data;
- all lifecycle and save boundaries have observable cleanup hooks or defensive invariant checks;
- no custom relationship serialization is required.

The asset/presentation portion remains IN PROGRESS. Production relationship code may begin only after one native candidate and bounded anchor strategy are identified. Any ordinary-click Harmony hook must validate exact signatures/tokens and be inert when no active pair exists.

## Kingmaker movement caveats that constrain implementation

- `UnitEntityView.MoveTo` `0x0600184D` and turn-based precomputed-path calls address stock `AgentASP` directly, bypassing `AgentOverride`. An override alone does not stop rider pathing.
- `UnitMovementAgent.UpdateUnitAvoidance` also inspects another unit's stock `AgentASP`. The transition must call rider `AgentASP.Stop()` `0x060018C2`, acquire exactly one `AvoidanceDisabled` lease, then disable it before installing the owned override.
- `AvoidanceDisabled` is a `CountingGuard`, not an idempotent Boolean. Cleanup releases only the lease KMC acquired and restores the captured enabled state.
- `UnitMoveContiniously.Init` `0x060026F0` may replace/destroy an override before the ordinary command-run event. Pair validation therefore requires no pre-existing override; continuous-control entry cleans up before proceeding.
- Assigning null to `AgentOverride` destroys the current override. Cleanup clears it only when reference equality proves KMC owns it.
- `UnitEntityData.Translocate` `0x06008345` is the supported entity/view relocation primitive for a validated nearby dismount location. Phase 1 does not write private movement caches.
